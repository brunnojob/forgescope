# Java/.NET architecture — 0.3.0

1. Java reads a bounded, UTF-8 repository inventory without following symlinks. Target source never becomes a runtime classpath.
2. Java source is parsed and semantically analyzed with `JavacTask`, `Trees` and an isolated empty classpath. `-proc:none` disables annotation processors; no class files are emitted and target initializers are not invoked.
3. C# source text is sent over bounded stdin JSON to an explicitly selected .NET worker DLL. Roslyn compiles only in memory against framework metadata; no MSBuild workspace, project analyzer, generator or emit step is used. Source declarations, calls, missing member leads and diagnostics return over stdout JSON.
4. Typed-source references form directed file dependencies. Reverse BFS records evidence chains and test candidates. Missing references remain review leads; diagnostics from absent external dependencies remain visible.
5. Java runs the review-rule ports, normalizes findings, associates file evidence and writes HTML/JSON/Markdown/SARIF. The optional JDBC writer appends to the original SQLite `runs` schema through prepared statements.
6. Portable HTML is generated by Java and contains no script. The local ASP.NET Core application implements server-side GET filters and a nonce-protected POST scan form. It binds to 127.0.0.1, checks Host/Origin, fixes the repository at startup and invokes Java with `ProcessStartInfo.ArgumentList` and no shell.
7. Patch validation is a separate Java command. It executes explicit, trusted test argv in a detached Git worktree, requires fail-before/pass-after, and cleans only the disposable checkout. This is edit isolation, not a security sandbox.

## Data ownership

Raw inventory/full logs are not placed into reports. Derived compiler diagnostics and finding evidence can still be sensitive. Redaction is incomplete. No source upload, cloud database, login or telemetry service is implemented.

## Build

The Java source launcher compiles/package classes with JDK tools; Maven is optional. The .NET SDK supplies Roslyn and ASP.NET Core. SQLite JDBC/SLF4J are explicit build-time dependencies with pinned hashes. No Python/Node runtime or custom JavaScript application logic remains.

## Presentation languages and tour

`src/main/resources/i18n.json` is the shared PT-BR/ES catalog; English is the stable source wording. Java emits `index.html`, `pt-br.html` and `es.html` with translated UI, generated explanations and a six-step anchor tour. Native CSS `:target` opens the active step and highlights its section; no browser script or third-party tour service is used. URLs preserve the selected language and tour step. Reduced-motion preferences disable the transition.

The C# workbench embeds the same catalog and styles. Its GET form selects all three languages, filters localized titles/actions as well as raw evidence, and POST scans preserve language/theme. Paths, symbols, raw log excerpts and compiler diagnostics remain original evidence. Exported JSON/SARIF remain stable machine formats. New rules must add both translations before release.

## Evidence-backed Pages demonstration

The report renderer now builds a six-stage, JavaScript-free tour from the actual report object. It displays the diff findings (PatchScope), CI and source-import findings (CIFuse), repository health (RepoRelief), Java/Roslyn source paths, RevScope file-header signals and export links. The fixture includes an empty PCAP header, explicitly labeled as a sample; no packet contents are analyzed. Each translated tour uses the same unmodified source evidence. This is not upstream engine feature parity; see README boundaries.
